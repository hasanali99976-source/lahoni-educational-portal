# بوابة أستاذ لحوني التعليمية — إعادة التأسيس V2

هذه النسخة إعادة تأسيس كاملة وليست ترقيعًا للتصميم القديم.

## ثوابت لا تُمس
- الحفاظ على بيانات المستخدمين والطلاب والمعلمين والمحفوظات الحالية.
- الحفاظ على سجلات الحضور والتحضير والدرجات والجداول أثناء الانتقال.
- عدم حذف بيانات إنتاجية أثناء إعادة البناء.
- عدم استبدال Production قبل نجاح اختبارات النسخة الجديدة.

## التصميم الموحد
- RTL عربي كامل.
- واجهة مدرسية بسيطة وهادئة وموحدة.
- نفس الرأس والقائمة والبطاقات والأزرار والجداول والنوافذ والتنبيهات في الإدارة والمعلم والطالب وولي الأمر.
- متجاوبة للجوال والكمبيوتر.
- لا إعادة استخدام لتصميم الصفحات القديم؛ يتم استبداله بمكونات V2 موحدة.

## مصدر البيانات
- الإدارة هي المصدر الرسمي للطلاب والفصول وصلاحيات المعلمين.
- جميع بوابات المستخدمين تستهلك طبقة API خادمية موحدة بدل تعدد المصادر المحلية.
- هوية سجل الطالب ثابتة عند النقل بين الفصول لمنع التكرار وحماية التاريخ.

## قواعد منع الاستنزاف
1. لا polling دوري لبيانات Firestore.
2. لا retry loops تلقائية غير محدودة.
3. لا قراءة سحابية عند كل نقرة أو تغيير واجهة.
4. لا كتابة عند عدم تغير القيمة.
5. لا أكثر من مصدر رسمي لنفس قائمة الطلاب.
6. Cache خادمي محدود وواضح للبيانات كثيرة القراءة.
7. إبطال cache بعد عمليات الإدارة التي تغير الطلاب أو الفصول أو الصلاحيات.
8. البيانات المتغيرة مثل الحضور والدرجات تستخدم cache قصيرًا مع invalidation بعد الحفظ.
9. منع الطلبات المتزامنة المكررة لنفس المورد عند الإمكان.
10. لا عمليات ترحيل أو backfill تلقائية عند فتح الصفحات.

## نطاق V2
### الصفحة الرئيسية وتسجيل الدخول
- هوية واحدة للبوابة.
- توجيه واضح حسب نوع الحساب.

### الإدارة
- المعلمون والصلاحيات.
- الطلاب والفصول والنقل والترحيل.
- تحديد مواد وفصول المعلم.
- التقارير الأساسية.

### المعلم
- الرئيسية / يومي.
- الجدول الدراسي.
- الحضور.
- التحضير.
- الدرجات.
- الطلاب والتقارير.
- العدد المعروض دائمًا من القائمة الرسمية الفعلية.

### الطالب وولي الأمر
- البيانات الشخصية والدراسية.
- الحضور.
- الدرجات.
- ما ينشره المعلم للطالب فقط.

## مفتاح عزل البيانات
المعلم + المادة + الصف + الفصل + التاريخ + الحصة عند الحاجة.

## خطة الاستبدال الآمن
1. بناء V2 على فرع مستقل من آخر Production مستقر.
2. إنشاء Design System موحد ومكونات Layout جديدة.
3. بناء API موحد للـ roster والصلاحيات والجدول.
4. إعادة صفحات الإدارة والمعلم والطالب وولي الأمر على V2.
5. قراءة المحفوظات الحالية دون حذفها أو إعادة كتابتها جماعيًا.
6. اختبار فصلين للمعلم في نفس اليوم والحصة وعدم اختلاط البيانات.
7. اختبار إضافة طالب ونقله وتعديله من الإدارة وانعكاسه على المعلم.
8. اختبار الحضور والتحضير والدرجات من الجوال والكمبيوتر.
9. مراجعة runtime logs وقراءات/كتابات Firestore للتأكد من عدم وجود حلقات استنزاف.
10. Build ناجح ثم Preview ثم Production بعد التحقق فقط.
